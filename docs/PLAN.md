# PLAN｜会议纪要生成 技术方案

## 交付形态

- CLI：本地运行 pipeline，输入 transcript，输出纪要文件
- HTML：本地生成双栏页面
  - 左侧纪要
  - 右侧原文与 cleaned version
- 第一版先不做点击高亮交互

## 本次升级范围

- 接入音频转写（ASR）
- 接入视频转写（视频走音轨提取后进入 ASR）
- 统一输出标准逐字稿，再进入现有分析链路
- 不接入图片 OCR
- 不做图片/白板/截图类输入

## 技术路线

- Python 3.12
- 固定 pipeline，而非 agent 编排
- 模型可配置，不固定 provider 或 model
- 统一模型接口，业务逻辑不直接依赖某家 SDK
- 媒体处理只做前处理，不改变后续纪要分析逻辑

## 模块划分

- `validate.py`: 输入校验与规范化
- `cleanup.py`: 原文清洗与 cleaned version 生成
- `media_ingest.py`: 音视频输入识别、文件校验、任务创建
- `asr_adapter.py`: 音频/视频转写适配
- `media_extract.py`: 视频音轨提取
- `classify.py`: 会议类型自动判定
- `templates.py`: 会议模板注册与选择
- `generate.py`: 结构化纪要生成
- `verify.py`: 规则校验
- `render.py`: Markdown / HTML 导出
- `pipeline.py`: 串联全流程

## 第一阶段目标

- 跑通最小闭环
- 先用构造样例验证流程
- 真实模型接口可接入
- 输出 Markdown 和 HTML
- 类型混合、长会、复盘部署类会议优先退到通用模板
- 音频和视频可统一转成逐字稿后进入现有分析链路
- 转写失败时保留明确错误，不影响已完成的纪要分析流程

## 内部跑通阶段

先不改页面，先把后端链路跑通到“可产出逐字稿并进入分析”：

### 阶段 1：媒体接入

- 支持上传音频文件
- 支持上传视频文件
- 校验文件类型、大小、时长
- 为每个媒体文件创建独立任务

### 阶段 2：转写产物

- 音频直接进入 ASR
- 视频先提取音轨，再进入 ASR
- 输出统一逐字稿结构
- 保留时间戳、说话人、片段顺序

### 阶段 3：分析串联

- 逐字稿进入现有 `cleanup -> classify -> templates -> generate -> verify -> render`
- 不改现有分析提示词主链路
- 只在输入层增加媒体转写结果

### 阶段 4：内部验证

- 用构造音频、构造视频和已知逐字稿做三组验证
- 检查转写准确率、分段稳定性、说话人可用性
- 检查分析结果是否还能稳定落到 `议题 / 结论 / 待办`

### 阶段 5：再改页面

- 内部流程稳定后，再补前端上传入口
- 再做转写进度展示
- 再做转写结果预览和二次编辑
