# 三段式纪要测试集｜会议概要 / 会议议题 / 待办事项

目标是验证当前产品能稳定生成更接近人工总结的会议纪要结果，最终只看三部分：

- `会议概要`
- `会议议题`
- `待办事项`

## 判定原则

- `会议概要` 允许模型做压缩总结，但不能编造事实。
- `会议议题` 需要覆盖会议中的核心主题、争议点和未决问题。
- `待办事项` 只保留明确行动项，负责人和时间仍必须可追溯。
- 只要三部分完整、信息可信、读起来像一份可交付纪要，就算通过。

## 建议最小回归集

1. `project_sync_001`
2. `decision_review_001`
3. `brainstorming_002`
4. `general_no_conclusion_001`
5. `interleaved_topics_003`
6. `speaker_missing_all_001`

## 建议观察点

- `会议概要` 是否真的总结了会议，而不是重复原文。
- `会议议题` 是否按主题归纳，而不是按发言顺序机械罗列。
- `待办事项` 是否漏掉关键动作，或错误补了负责人和时间。
- 无结论会议是否仍然保留“未决”表达。
- 缺 speaker 的会议是否还能正确空掉 owner。
